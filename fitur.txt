================================================================
FITUR APLIKASI SSO (Identity Provider)
https://sso.ukpbj.demakkab.go.id
Teknologi: Laravel 12 + Passport 13 (OAuth 2.0 / OIDC) + MySQL 8
================================================================

== 1. AUTENTIKASI TERPUSAT ==
- Login Single Sign-On (SSO) dengan satu akun untuk semua aplikasi klien
- Identifier fleksibel: bisa EMAIL atau NIP (deteksi otomatis via FILTER_VALIDATE_EMAIL)
- Password disimpan hashed (bcrypt 12 rounds)
- Audit login: mencatat waktu login terakhir (last_login_at) & IP (last_login_ip)
- Proteksi status akun: hanya user dengan status "active" yang bisa login
  (user suspended/inactive otomatis ditolak)
- Pesan validasi bahasa Indonesia (contoh: "Email atau NIP wajib diisi.")
- Session fixation protection: session diregenerate saat login & logout
- WAJIB GANTI PASSWORD pada login pertama:
  * Password buatan sistem / hasil reset admin menandai must_change_password
  * Login -> langsung diarahkan ke /password/change
  * Semua halaman lain (dashboard, sessions, admin, /oauth/authorize, dll)
    dialihkan kembali ke /password/change sampai password diganti
  * Halaman ubah password: verifikasi password lama, password baru minimal
    8 karakter, harus berbeda dari yang lama, + konfirmasi
  * Setelah berhasil: flag dimatikan, password_changed_at diisi, session
    di-regenerate, user dikembalikan ke tujuan semula (mis. /oauth/authorize)
  * Logout tetap diizinkan; request JSON/API dijawab 403
  * Admin dapat menandai/membatalkan lewat checkbox di Edit User
- UBAH PASSWORD MANDIRI (semua role: admin & user):
  * Tombol "Ubah Password" di dashboard IdP + link di header
  * Verifikasi password lama, password baru minimal 8 karakter & berbeda
  * Setelah sukses: session di-regenerate, password_changed_at diperbarui,
    dashboard menampilkan notifikasi "Password berhasil diubah"
  * Tidak dibatasi role (user biasa tidak mendapat 403)

== 2. OAUTH 2.0 / OPENID CONNECT (via Passport 13) ==
- Authorization Code flow dengan PKCE S256 (WAJIB - middleware pkce global)
- Implicit flow dilarang
- Scopes: * (penuh), openid, profile, email - default scope *
- Token endpoint (POST /oauth/token): grant authorization_code & refresh_token
- Access token berlaku singkat (15 menit) + refresh token 14 hari
- Refresh token rotation: token lama otomatis dicabut setelah dipakai
  (reuse refresh token lama -> 400 invalid_grant)
- Token revocation RFC 7009 (POST /oauth/revoke)
- OIDC UserInfo endpoint (GET /oauth/userinfo) - nama, email, NIP, sub
- JWKS endpoint (GET /oauth/jwks) - kunci publik RS256 (kid: passport-key-1)
- API endpoint /api/user - profil user via bearer token (401 JSON jika token invalid)
- Consent page kustom; client "trusted" melewati halaman consent
- Rate limiting POST /oauth/token: 15x/menit per kombinasi client_id + IP

== 3. SINGLE LOGOUT (SLO) ==
- Back-Channel Logout sesuai spec OIDC Back-Channel Logout 1.0
- Saat global logout, IdP mengirim POST logout_token=<JWT RS256> ke setiap
  aplikasi klien terkait
- Logout token berisi klaim: iss, aud, sub, sid, jti, iat, events (logout event)
- Aplikasi klien memverifikasi JWT via JWKS + anti-replay (jti), lalu
  menghancurkan sesi lokalnya otomatis
- Saat logout global: seluruh access & refresh token user dicabut,
  semua mapping sesi (sso_sessions) ditandai berakhir
- Audit pengiriman tersimpan di tabel sso_logout_audit
  (status delivered/failed, http_status, respons IdP klien)
- Front-channel logout (opsional, per client) sebagai alternatif via iframe browser

== 4. JENIS LOGOUT ==
- Logout LOKAL di aplikasi klien ("Keluar (Aplikasi Ini)"):
  sesi aplikasi tersebut berakhir, sesi IdP TETAP AKTIF,
  user diarahkan ke dashboard IdP, bisa masuk lagi tanpa login ulang
- Logout GLOBAL di dashboard IdP ("Logout (semua aplikasi)"):
  sesi IdP + semua aplikasi klien berakhir sekaligus (back-channel)
- Tombol "Logout Semua (SSO)" di aplikasi klien: memanggil global logout IdP

== 5. TRACKING SESI & PERANGKAT ==
- Tabel sso_sessions: mencatat setiap login/authorize per perangkat
- Halaman /sessions: daftar perangkat & sesi aktif milik user
- Putus sesi per-perangkat (revoke satu perangkat tanpa memengaruhi lainnya)
- Housekeeping sesi kedaluwarsa via SsoSessionService::purgeExpired()

== 6. PANEL ADMIN (role admin saja) ==
- Dashboard admin: statistik (total user, user aktif, suspended, jumlah
  aplikasi klien, sesi SSO aktif, jumlah admin) + daftar user & klien terbaru
- CRUD USER:
  * Field: nama, email, NIP (WAJIB), nomor WhatsApp, role, status
  * Password TIDAK diisi admin: dibuat otomatis 12 karakter
    (tanpa karakter ambigu 0/O, 1/l/I) lalu dikirim ke WhatsApp user
  * Jika pengiriman WhatsApp gagal: user tetap dibuat, password
    ditampilkan SEKALI di panel admin (tombol Copy) untuk diteruskan manual
  * Aksi "Kirim WA" (daftar user) & "Kirim Password Baru via WhatsApp"
    (edit user): membuat password baru + mengirim ulang
  * Kolom password_sent_at mencatat waktu pengiriman terakhir
  * Checkbox "Wajib ganti password saat login berikutnya" (must_change_password);
    otomatis aktif saat user dibuat / password direset / password diisi admin
  * Role: admin / user (kolom enum, tanpa package permission)
  * Status: active / suspended / inactive
  * Pencarian (nama/email/NIP/WhatsApp), filter role & status, pagination
  * Self-protection: admin tidak bisa mengubah role sendiri, tidak bisa
    menghapus akun sendiri, role akun sendiri terkunci di form
  * Hapus user = cabut semua token + akhiri semua sesi SSO miliknya
- CRUD APLIKASI KLIEN (OAuth Client):
  * Field: nama, redirect URIs (multi, URI ke-2 opsional boleh kosong),
    Landing URL, Back-Channel Logout URI, Front-Channel Logout URI,
    Trusted (skip consent)
  * Client ID otomatis (UUID), Client Secret ditampilkan SEKALI di halaman
    khusus (tidak bisa dilihat lagi; ada tombol Copy)
  * Regenerate secret: secret baru ditampilkan sekali, secret lama hangus
  * Revoke client (soft delete ala Passport: revoked=1) - semua token
    client ikut dicabut
  * Validasi: minimal 1 redirect URI, semua URI harus URL valid
- Hak akses: semua route /admin dilindungi middleware "admin";
  user role "user" mendapat 403 "Akses ditolak"

== 7. APLIKASI TERHUBUNG DI DASHBOARD ==
- Client klien yang punya Landing URL tampil sebagai kartu di dashboard IdP
- Klik kartu -> aplikasi klien dibuka di TAB BARU (target=_blank, rel=noopener)
- Alur SSO otomatis: user sudah login di IdP -> langsung masuk aplikasi
  tanpa isi ulang password
- Client tanpa Landing URL tidak tampil di dashboard

== 8. KEAMANAN ==
- Rate limiting POST /login: 5x/menit per IP dan per identifier (brute force)
- Rate limiting default: 60x/menit per IP
- Security headers: Content-Security-Policy, X-Frame-Options DENY,
  X-Content-Type-Options nosniff, Referrer-Policy, Permissions-Policy,
  HSTS saat HTTPS
- Session database (SESSION_DRIVER=database) + encrypted cookie
- Anti open-redirect: post_logout_redirect_uri & redirect divalidasi
  terhadap redirect_uris client
- CSRF protection (kecuali endpoint server-to-server: oauth/revoke &
  backchannel logout)
- Kunci OAuth: storage/oauth-private.key & oauth-public.key (RS256)
- TrustProxies + force HTTPS saat APP_ENV=production (siap di belakang Nginx)

== 9. INFRASTRUKTUR & OPERASIONAL ==
- URL produksi: https://sso.ukpbj.demakkab.go.id (APP_ENV=production, APP_DEBUG=false)
- Siap deploy di belakang reverse proxy Nginx/Apache (contoh konfigurasi di README)
- Seeder demo (SsoDemoSeeder): users demo (admin & budi) + client demo opsional
- Logout token builder memakai key passport dengan kid "passport-key-1"
- Stale JWKS fallback di sisi klien: verifikasi logout token tetap jalan
  meski IdP sedang sibuk/timeout (menghindari deadlock dev-server single worker)

== 10. ENDPOINT UTAMA ==
  GET  /oauth/authorize      Authorization endpoint (PKCE S256 wajib)
  POST /oauth/token          Token endpoint (code + refresh grant)
  GET  /oauth/userinfo       OIDC UserInfo (bearer)
  POST /oauth/revoke         Revocation (RFC 7009)
  GET  /oauth/jwks           JSON Web Key Set (kunci publik RS256)
  GET  /sso/logout           Single Logout (client_id + post_logout_redirect_uri)
  GET  /login, /logout       Login & global logout IdP
  GET  /sessions             Daftar perangkat & sesi aktif
  GET  /password/change      Form ubah password (wajib pada login pertama)
  PUT  /password/change      Simpan password baru
  GET  /api/user             Profil user via bearer token
  GET  /admin                Panel admin (role admin saja)

== 11. DATABASE ==
  sso_idp  -> database IdP (users, sessions, sso_sessions, sso_logout_audit,
              oauth_clients, oauth_access_tokens, oauth_refresh_tokens, dll)
  Kolom baru users: whatsapp, password_sent_at, must_change_password,
              password_changed_at

== 12. INTEGRASI WHATSAPP (FONNTE) - PENGIRIMAN PASSWORD ==
- Gateway: Fonnte (https://fonnte.com), HTTP POST ke FONNTE_API_URL
  dengan header Authorization: <FONNTE_TOKEN>
- Konfigurasi .env: FONNTE_TOKEN, FONNTE_API_URL, FONNTE_TIMEOUT,
  FONNTE_COUNTRY_CODE (config/services.php -> fonnte)
- Admin menambah user: isi nama, email, NIP, nomor WhatsApp, role, status
  -> sistem generate password 12 karakter & kirim via WhatsApp
- Isi pesan: nama aplikasi, sapaan, email, NIP, password, URL login,
  imbauan ganti password setelah login pertama
- Normalisasi nomor otomatis: 08xx / +628xx / 8xx -> 628xx
- Validasi nomor (Rule WhatsAppNumber): panjang wajar 10-15 digit,
  format salah ditolak sebelum user disimpan
- Fallback: bila token kosong / timeout / kuota habis, user TETAP dibuat,
  password ditampilkan sekali di panel admin (tombol Copy) + alasan gagal;
  kegagalan dicatat di log Laravel (channel default, prefix "Fonnte:")
- Kirim ulang / reset: tombol "Kirim WA" di daftar user dan
  "Kirim Password Baru via WhatsApp" di halaman edit
  (password baru menggantikan password lama)
- Password yang dikirim sistem/admin WAJIB diganti user saat login
  (lihat bagian 1 - Wajib Ganti Password)
